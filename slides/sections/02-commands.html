Plan Mode

Read first, write second. Toggle Claude into read-only exploration, agree on a plan, then flip back to execute.

Toggle with Shift+Tab. Open the plan in your editor with Ctrl+G before you run it.

45 seconds. This is the recommended default for anything that touches more than one file. You get to see the plan before Claude edits anything.

Skip plan mode for one-line fixes. Use it when the scope is fuzzy, the blast radius is unclear, or you are somewhere sensitive on the client side.

Anthropic: "Use /clear frequently between tasks to reset the context window entirely."

60 seconds. Every file Claude reads, every command output, every turn piles up in the context window. Performance degrades as it fills. /clear gets you a fresh session without relaunching.

Rule of thumb: after two failed corrections on the same issue, clear and rewrite the prompt with what you just learned. Clean context beats a stack of corrections.

/clear wipes. /compact summarizes. Pick based on whether the next task is related to the last one.

45 seconds. Key distinction: /clear wipes everything; /compact preserves a summary. Use /compact when the work is related and you need continuity. Use /clear when it is not.

The optional instructions argument is underused. If you just spent 20 turns on auth but want to pivot to billing, /compact Focus on billing-related decisions lets you keep the useful context and lose the rest.

/rewind

Every action is a checkpoint. Restore the conversation, the code, or both — to any previous point.

↺ restore to: edit

~/captech/primer
$
checkpoint: edit session.ts
conversation restored
files restored
try risky things undo across sessions

Double-tap Esc. Checkpoints persist across sessions — rewind tomorrow if you need to.

30 seconds. This changes how you experiment. You do not have to plan every move carefully. Tell Claude to try something risky — if it fails, rewind.

Caveat: checkpoints track Claude's changes, not external processes like migrations or deployments. Not a replacement for git.
