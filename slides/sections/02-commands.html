02 of 05

/clear

Reset context between unrelated tasks. The single most-recommended habit.

> /clear

Anthropic: "Use /clear frequently between tasks to reset the context window entirely."

60 seconds. Walk through: "Every file Claude reads, every command output, every turn — it all stacks in the context window. Performance degrades as it fills. `/clear` is how you get a fresh session without relaunching."

Rule of thumb: after two failed corrections on the same issue, `/clear` and rewrite the prompt with what you learned. Clean context beats accumulated corrections.

03 of 05

/compact [instructions]

Summarize the conversation to free context while keeping decisions. Pass optional instructions to bias the summary.

Before · 47 turns
⇢

Decisions made

Example: /compact Focus on the API changes preserves API context, drops the rest.

45 seconds. Key distinction: `/clear` wipes everything; `/compact` preserves a summary. Use `/compact` when the work is related and you need continuity. Use `/clear` when it isn't.

The optional instructions argument is underused. If you just spent 20 turns on auth but now want to focus on billing, `/compact Focus on billing-related decisions` lets you keep the useful context and lose the noise.

04 of 05 · Esc Esc

/rewind

Every action is a checkpoint. Restore conversation, code, or both — to any previous point.

↺ restore to: edit

Double-tap Esc. Checkpoints persist across sessions — rewind tomorrow if you need to.

30 seconds. Say: "This changes how you experiment. You don't have to plan every move carefully. Tell Claude to try something risky — if it doesn't work, rewind."

Caveat: checkpoints track Claude's changes, not external processes. Not a replacement for git.
