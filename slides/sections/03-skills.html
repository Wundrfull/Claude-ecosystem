What it actually is

A skill is a folder with SKILL.md. That is the whole contract.

~/.claude/skills/commit-message/
commit-message/
└── SKILL.md    # required entrypoint
commit-message/SKILL.md
---
description: Use when the user asks for a commit message for
  staged changes. Reads git diff --cached and produces a
  short conventional-commits summary.
---

Read the staged diff. Summarize in one line using
conventional commits. Reference the diff; do not restate it.

The folder name becomes the slash-command. Drop it in, type /commit-message, done.

60 seconds. Lean on what the team already knows: no plugin, no manifest, no registry. A folder with a markdown file, and you have shipped a skill.

Save the file and it is live on the next turn. No restart, no reload.

Names and one-line descriptions live in context. The body only loads when Claude picks the skill. A 2,000-line skill costs you nothing until you need it.

90 seconds. This is the idea that unlocks the rest. You can install 30 skills and not pay a context tax, because only the names plus a 1,536-character description sit in context. The body comes in on invoke.

Corollary for later: the description is the activation lever. Vague description, Claude skips the skill. We will come back to this.

Frontmatter reference

description is the only one you need. The rest are tuning knobs.

description What it does and when to use it. The first 1,536 characters are the whole index entry. Lead with the "use when" trigger.
disable-model-invocation: true Manual-only. Good for anything with side effects: /deploy, /commit, /send-slack.
allowed-tools Pre-approve tools while the skill is active. Bash(git add *), Bash(git commit *) stops the approval spam.
context: fork Run the body as the prompt to an isolated subagent. Pair with agent:.
agent: Explore | Plan | general-purpose Which subagent type executes the forked context. Explore is read-only; Plan is planning-focused.
paths Glob patterns. The skill auto-loads only when Claude touches matching files.

90 seconds. Walk top to bottom. For this team today, the two that matter most: disable-model-invocation on anything with side effects, and allowed-tools to stop the approval-prompt spam mid-demo.

Two knobs that extend skills · 60s aside

Where subagents and hooks fit

Subagents

Add context: fork plus agent: Explore to your SKILL.md. The body becomes the task; an isolated context window does the work.

main session
$
forking · agent: Explore
child window · 0 tokens
done · returned 3-line summary

Use for research, code review, anything that would otherwise pollute your main conversation.

Hooks

Shell commands that fire on tool events. Deterministic, unlike CLAUDE.md instructions. Configured in .claude/settings.json.

PostToolUse hook
$
wrote 1 file
hook fired · npm run lint
lint passed · continuing

Use to block force-push without a flag, run lint after every edit, or enforce what CLAUDE.md can only request.

60 seconds flat. No deep dive. The job is name-recognition so "subagent" and "hook" land as familiar words when they come up on the job next week.

Mental model to say out loud: skills are the playbook, subagents are where it can run, hooks are the guarantee.

The one rule that breaks most skills

Descriptions say when, never what.

what — skipped

description: Reviews code for bugs, suggests refactors, and writes a summary.

when — invoked

description: Use when the user asks for a code review or says "look over this diff."

If the description summarizes the workflow, Claude follows the description and never reads the body. This is how the Superpowers "code review between tasks" bug happened.

60 seconds. Read the quote twice — once fast, once slow. Then land the failure mode: if your description says "do X then Y," Claude may do just X and never open the body.

Third-person triggers. Symptoms. "Use when the user asks..." That is the pattern.
