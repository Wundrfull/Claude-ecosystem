Subagents + hooks

Aware-only. Two powerful primitives. Brief tour.

Primitive 1

Subagents

  • A focused helper agent you spawn mid-session.
  • Owns its own context window.
  • Reports back summarized.

Anthropic frames them as parallelism. The community framing is stronger: subagents are a quality gate. A fresh subagent per task, plus a spec-compliance reviewer and a code-quality reviewer.

Token-expensive. Only worth it for larger tasks.

Inherits your permissions

2.5 minutes. Don't demo; describe. The quality-gate framing is what you want them to remember.

One concrete example

Spawn a code reviewer.

> Spawn a code reviewer subagent on these 3 files:
  graph/resolver.go
  loader/product.go
  graph/schema.graphqls

Criteria:
  - does it follow the "never edit generated" rule from CLAUDE.md?
  - are resolvers using dataloaders where available?
  - cite file:line for any issue

Result comes back summarized. Don't trust the summary. Inspect the diff.

Say: "Don't trust the summary. Inspect the diff." Emphasize verification even on helpful output.

Primitive 2

Hooks

  • Shell commands that run in response to tool-call events.
  • Events: PreToolUse, PostToolUse, TeammateIdle, TaskCompleted.
  • Exit code 2 sends feedback to Claude and keeps it working.

The mechanical enforcement layer for CLAUDE.md rules.

2.5 minutes. Hooks are the "how I make Claude physically unable to do X" primitive.

One concrete example

Block git push --force.

.claude/settings.json — PreToolUse hook
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "command": "bash -c 'if echo \"$CLAUDE_TOOL_INPUT\" | grep -qE \"git push .*--force(-with-lease)?\"; then echo \"force push blocked by CLAUDE.md policy\" >&2; exit 2; fi'"
      }
    ]
  }
}

Enforces the CLAUDE.md rule mechanically. The model cannot bypass it by forgetting.

Client-ready — audit the commands

Hook commands run with your shell. Audit them. Don't install arbitrary hooks from the internet.
